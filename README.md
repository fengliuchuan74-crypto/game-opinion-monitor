# App Store 舆情工作台 2.3

面向任意 App Store 游戏与地区的本地运营工具：真实采集 → 图表分析 → 问题定位 → 具体处理建议。页面面向汇报与演示，保留真实业务数据和可解释的统计口径。

本仓库是可移植源码版，包含应用、深色界面、测试与锁定依赖；不包含原电脑的 Python 运行环境、真实评论数据库、缓存、日志、导出报告或 Codex 登录信息。首次启动会建立空白本地数据库。

## 内置 Agent 分析

在「舆情概览」选择 **Agent分析**，默认选择「全部待分析评论」，点击「开始 Agent 分析」即可处理当前游戏、地区及统计区间的全部待分析评论，不受 30 条或 1000 条任务上限限制。也可选择「自定义数量」。任务在后台运行，显示总体进度；可以取消，失败后可重试。已经通过校验的评论分析会保存，重复分析会复用同一原文、模型和提示版本的结果。评论修改后自动失效，不修改原始评论。任务启动时固定评论范围，之后新采集的评论留给下一轮。

选择 **规则初筛** 后，标题、分析内容、图表、处理参考及导出都采用本地规则结果，隐藏 Agent 操作与运行历史。对已采集评论的初筛无需联网；游戏图标沿用本地缓存。选择 Agent 后恢复已有 Agent 结果。两种方式保持相同看板结构，人工复核优先。

图表下方的「Agent逐条解读」或「规则分类明细」可展开查看完整评论原文和对应判断。Agent 结果包含判断理由、玩家诉求与原文依据；支持按分析状态、情绪、问题类别筛选、搜索原文及翻页。未分析评论单独标记，不用规则结果替代。

流程为：采集入库 → Agent 逐条识别情绪、多主题、具体诉求及原文依据 → 程序计算统计 → Agent 选择需要进一步调查的类别与评论 → 工具查询本地本期和上期记录 → Agent 生成观察、待验证原因、处理步骤、建议协作及验收方式。统计数字由程序计算，模型不能任意执行命令或访问其他文件。引用必须属于本次评论，逐字引文须通过原文校验。

十张图、逐日详情、典型评论与 Excel/HTML/Markdown 导出共用当前分析口径。Agent 模式下未完成分析的评论显示待分析/待判定，不混入中性评价；星级、声量和关键词仍来自原始样本。低星风险提示与监控提醒继续使用明确的规则阈值。可切回「规则初筛」对照。报告显示生成时的数据范围；新增评论或人工更正后会提示报告过期。

Agent 模式下，「采集与设置」可启用当前游戏/地区采集后的自动分析，默认关闭；可设置最近 1—365 天与每轮 10—1000 条预算。手动选择全部不会修改自动分析预算。较多评论由后台分批连续处理，再执行核查及报告调用，耗时和额度取决于当前 Codex 模型及评论长度。队列、批次、结果及报告保存在本地数据库，重启恢复未完成任务；工具关闭时不运行。运行记录与连接检查收在「运行详情与连接设置」。

使用本机已安装并登录的 Codex CLI，复用其模型、服务商和认证，不在网页或数据库另存密钥。可在设置中「检查 Agent 连接」；未安装或未登录时显示引导，评论采集仍可正常进行。换电脑需要在新电脑安装并登录 Codex，Python 运行包不包含 Codex。可通过环境变量 `APPSTORE_CODEX_BIN` 指定可执行文件。本地选中评论会发往当前 Codex 配置的模型服务进行分析；计费与额度沿用该配置。

当前接入 App Store 评论；尚未接入 B 站。Agent 输出是有证据的辅助判断，未经过整体准确率标定，原因假设需结合项目日志及业务数据核实。

## 启动与停止

已验证运行环境：Windows、Python 3.12.10。源码使用相对路径；推荐以 Python 3.12 建立独立环境。在仓库根目录打开 PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -X utf8 -B launch.py
```

如果没有 `py` 命令，确认 `python --version` 为 Python 3.12 后，用 `python -m venv .venv` 替代第一行。无需激活环境，后续命令直接使用虚拟环境中的解释器。`requirements.txt` 和 `requirements.lock.txt` 均保留交付版验证过的锁定版本。联网安装依赖需能访问所配置的 Python 包源。

启动后访问终端显示的本地地址，通常为 `http://127.0.0.1:8501/`。使用 `launch.py` 同时管理页面、采集巡检和 Agent 后台任务。可传入 `--no-browser` 不自动打开浏览器，或 `--port 8502` 指定首选端口。

启动器会选择空闲本地端口、打开浏览器并输出日志位置。重复启动只打开已有实例。浏览器标签页关闭后巡检继续；在启动窗口按 Ctrl+C，或另开终端执行以下命令退出工具并停止巡检：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B launch.py --stop
```

电脑休眠或关机期间不会采集，下次启动补跑到期任务。服务仅监听 `127.0.0.1`。默认数据写入 `data/`、报告与日志写入 `outputs/`；可用环境变量 `APPSTORE_DATA_DIR` 指定数据目录。停止或恢复时须使用同一个数据目录设置。采集需要访问 Apple 公开接口；已入库评论的规则初筛可离线运行。

## 第一次使用

1. 在左侧「当前游戏与地区」选择已有游戏，或选「＋ 添加游戏」。可以按名称搜索、核对发行商和商店页面，也可以填写商店网址中的数字 App ID。
   首页标题卡片右侧展示该游戏的官方 App Store 图标，随游戏和地区切换。新搜索游戏沿用搜索返回的图标，Agent 模式可按 App ID 自动补取；规则模式只读缓存。图标缓存在 `data/app_icons`，有效期 7 天，离线保留上次成功图片。首次获取失败时显示游戏名称首字占位，联网模式 5 分钟后可重试，不影响评论分析。
2. 选择正确地区；同一游戏多个地区需分别添加，评论与巡检配置独立保存。地区图仅对比同一 App ID。
3. 顶部展示当前游戏/地区累计已采集数量、评论最早与最晚时间，以及「立即采集最新评论」「采集日志」。采集进度每 3 秒局部更新，显示本次读取、新增和时间范围，支持暂停、继续、结束（保留已存评论）。采集期间不因每页入库重算整张看板；完成或暂停后刷新。日志按日期分组，用颜色区分运行、成功、部分成功、重试、暂停和失败，详情说明实际覆盖和停止原因。
4. 在「采集与设置」选择最新增量、固定日期补采或历史回溯。扫描上限可设 500、5,000、10,000、50,000 条，或自定义 50—1,000,000 条；这是本次扫描预算，包含重复及日期范围外评论，不是保证能读取的源站总数。新增巡检默认间隔 30 分钟、最多扫描 5,000 条；可选 15 分钟至 24 小时、每轮最多 100,000 条。已有配置保留，历史游戏不会被擅自开启巡检。
5. 在「舆情概览」查看八项核心指标、分析结论和十张交互图：情绪分布、星级分布、声量趋势、情绪构成趋势、低星/均分走势、主要问题走势、版本口碑、地区对比、问题类别、关键词排行。有数据时绘图，无数据明确显示空状态。
6. 趋势可按日/周/月查看；「⤢ 放大图表」优先打开适应屏幕的大图。默认拖动平移，图内中文工具栏可切换「框选缩放」，放大后切回平移会保留当前视野；双击或点「恢复全图」还原。滚轮用于上下浏览，长类别/关键词榜单可滚动到末尾；工具栏可下载 PNG。趋势窗口的「按天细看」按需加载，来回切换会保留日期与筛选，也可从概览直接打开逐日详情。
7. 页面下方的「具体处理方案与代表评论」直接提供核实步骤、协作团队、处理方法、验收方式和中英文回复参考，无需创建事项。
8. 在「数据与导出」生成 Excel 分析数据与建议、HTML / Markdown 简报。Excel 附有每日趋势、情绪、星级、版本、问题与关键词统计；HTML 附有四组可离线查看的图形摘要。

## 演示页面与配色

沿用原版深色背景与紫色主色；好评使用清透青绿、差评使用明亮莓果粉，中评使用蓝色，待判定使用淡紫；同一情绪在不同图表中使用一致颜色。卡片沿用深灰底与细边框。核心指标、问题提示、分析卡片与图表分别强化重点。侧边栏提供舆情概览、监控总览、评论浏览、采集与设置、数据与导出五个独立入口。

本版取消「证据与复核」「处理台账」入口及建立事项按钮。代表评论仍可在主题和关键词中直接查看。历史库中的复核结果与处理记录保留，兼容已有数据。

## 逐日细看、分类与典型评论

- 逐日详情：选择任意一天或使用前一天/后一天；查看当天全部类别，切换全部/负面相关评论；选择类别后阅读对应原文或下载 Excel。当天数据始终与主看板的游戏、地区和统计区间一致。
- 「问题类别与关键词」共用版本筛选，沿用主看板统计时间，同时过滤问题类别、关键词和对应评论原文。类别展示当前筛选样本的评论数与占比，可选全部类别或前 12 类；不在该排行展示本期/上期对比。走势默认显示所有主题的堆叠柱形，可改为前 5 类。页面显示分类覆盖率和支持的主题清单。
- 关键词按提及评论数统计，支持前 10/20/30 名。由深紫灰向青绿渐变，越亮频率越高；类别排行使用紫色渐变。
- 侧边栏新增「全部已采集历史」，便于对照长时间事件；历史数据不等于完整商店历史。
- 「典型评论卡片」包含典型好评、典型差评、最新负面、内容与玩法四组。采用作者/日期、星级、情绪与主题标签、商店来源和建议区；长文本支持展开。典型好评排除情绪尚未确认的高星评论，不足 5 条时如实展示。公开源没有可靠互动统计，因此不标为高互动排行。
- 放大窗口固定打开时的数据快照，避免阅读期间口径变化；关闭窗口回到随采集刷新的看板。

## 监控能够保证什么

- 优先读取 Apple 公开商店页面提供的评论列表，使用该地区的商店请求头，按最新发表排序、每批 50 条连续读取。校验游戏 ID、地区和返回的评论地区标记。首页读取失败时兼容同地区 RSS；一旦开始分页，中途不混用来源，避免漏页或重复。未知商店代码仍尝试 RSS。两个公开入口都不需要开发者账号。
- 网络错误自动重试一次；整轮失败记录原因，并延长下次自动重试间隔。手动按钮仍可请求下一轮。
- 新评论插入，同一外部评论 ID 的正文、星级、版本修改会更新并保留旧版本；不覆盖日期更晚的已有版本。
- 每个游戏/地区有持久化采集记录、排队状态、下一次巡检时间和并发锁，重复打开页面不会重复发起同一任务。
- 新出现或变化的 P1 主题仍会写入本地提醒记录用于审计；「监控总览」展示各游戏、各地区的采集状态，「评论浏览」独立提供评论原文、分析状态和范围筛选。在状态下拉框选择「待复核」即可查看相关评论，不再重复提供快捷按钮。
- 定时从最新向前翻页，重扫到上次成功接收的最新评论之前 24 小时。不能衔接时保留原采集水位，提示缺口；分页重叠、重复页、时间乱序或缺失时不确认连续性。只是达到所设页数而未到起点，不会延长正常巡检间隔。

公开 RSS 并非推送接口，Apple 可能延迟、限流、限制页数或不提供某地区数据。因此工具提供近实时巡检，不承诺秒级更新、完整历史或跨平台全网舆情。失败时保留旧库并显示状态，不把无数据解释为无负面。

## 日期范围、数量与连续覆盖

- **立即采集最新评论**：最多扫描约 5,000 条，并回扫上一成功水位之前 24 小时以衔接。按最新到最旧读取，每页通常约 50 条，日期跨度取决于评论密度，与左侧分析的「近 7 天」筛选无关。
- **按日期补采**：进入「采集与设置 → 本次采集范围」，选择「按固定日期补采」，选择起止日期与扫描数量上限，再提交。日期按北京时间，包含起止两天；今天只取任务固定结束时刻之前。按页向历史回溯，只有范围内的评论入库；未到起点会明确显示部分成功。
- **历史回溯与数量上限**：公开评论列表支持超过 10 页的深分页；单次任务最多可设 20,000 页（约 100 万条扫描预算）。每批至多 20 次页面请求后让出工作线程供其他游戏使用，评论正文按页释放，数据库每页保存。兼容 RSS 仍最多 10 页，其限制不套用于公开列表。预算不是源站可读总量承诺。
- **可靠续采**：暂停、网络失败或进程重启后使用数据库断点续采，并回扫两页以检查旧评论 ID 的衔接。评论与断点在同一事务保存，过期任务不能覆盖新任务；按游戏、地区和评论 ID 去重。429 限流按源站等待时间或指数退避等待，同站其他游戏也暂停请求；连续六次无进展失败后暂停待继续。结束任务保留已采集数据。重新启动工具即可恢复未完成任务，关闭工具期间不会运行。
- **结果说明**：每轮显示尝试页数、实际读取、区间内、入库新增、更新、重复、耗时、读到的最早/最新评论时间、停止原因和覆盖判断。0 条新增可能表示评论都已存在；读取 0 条并报源站空响应则表示本次采集未取得有效数据。
- **覆盖日历**：「采集与设置 → 逐日采集覆盖」逐日显示本地条数及公开源已遍历、部分遍历、未有遍历记录。多个可验证区间可以合并；旧库里的评论和合法导入文件只计数量，不自动被当作连续采集证明。
- **长期连续积累**：电脑开机、工具保持运行，在「采集与设置」启用巡检。高声量游戏可先选 15—30 分钟/5,000 条，按实际衔接情况调整。首次采集只建立本轮可见基线；历史回溯和日期补采不推进最新评论巡检水位。只有已入库的评论才能推进水位，有既有水位时还须完成连续衔接。Apple 延迟发布、修改或删除评论仍可能造成遗漏，回扫不能消除所有边界。

「公开源时段已遍历」只说明所见分页在该时段已被读取，不等于 Apple 已经发布该时段的所有评论，更不等于完整商店历史。公开 RSS 与公开评论列表均无法保证任意游戏的任意历史区间全量。若是自己发行的应用，可另外接入获授权的 App Store Connect 评论 API；其他游戏更早历史需要合法数据服务或历史导出文件。当前工具尚未接入这些额外数据源。

## 统计口径与判断边界

- 默认按中国时间（UTC+8）的今天 / 近 7 天 / 近 30 天；可选自定义历史区间。概览自动更新截至时间。导出页固定截至时间便于生成一致的报告，可点击「更新统计至当前时间」刷新。
- 前一期是紧邻当前起点的等长时间段；起止时刻均展示。未注明日期、未来日期不计入当期指标。
- 低星是 1—2 星，有效 1—5 星为分母；它是已获取评论的分布，不是商店累计评分，也不是全体玩家满意度。核心指标卡只显示当期值，已移除容易产生歧义的涨幅标记。
- 大盘提示要求至少 30 个有效星级样本。当前与上期都至少 30 条、低星至少 10 条且低星比例增加至少 15 个百分点，提示优先核查。低星至少 10 条且占比至少 40% 提示持续关注。没有足够样本时不展示涨跌结论。
- 「规则初筛」使用中英文词语、否定与主题规则，常见繁体表达会归一化；「Agent分析」使用已保存的大模型逐条判断。两者均未经过整体准确率标定。星级与正文冲突、混合语义或证据不足时可以标为待复核；星级统计独立保留。
- 一个评论可以涉及多个主题；主题条数不能相加当总人数。单条严重反馈是优先核查事项，不自动判定为已确认事故，不自动生成 P0。
- 类别建议是待核实的业务处理清单，不是已经证明的根因。原文更新后旧的人工复核会失效，避免继续沿用过时结论。

## 从分析到具体建议

每个负面主题提供当前及等长上期数量、原文与版本证据、建议协作团队、核实时间、验证清单、处理步骤、结果验收方式、中英文回复参考。P1 为优先核实，P2 为常规跟进；严重个案也不直接等同整体事故。

声量和情绪图统计当前游戏/地区。地区对比单独展示同一游戏已添加地区；没有有效星级时比例显示缺失，不画成 0%。趋势按中国时间，周从周一开始，首尾可能是不完整周期。空档表示本地未获取评论，不证明商店没有评论；均分和比例留空。多主题评论在每个主题最多计一次，主题总数可能超过评论量。关键词按提及评论数去重，去除当前游戏名称和版本元数据；关键词本身不证明原因。

建议结合版本上线、活动、服务监控和客服工单核实分析线索，再由相关团队实施处理。工具提供建议，不自动向商店发布内容。

## 数据导入与导出

支持 CSV / XLSX / XLS，单次最多 20 MB。页面可下载空白模板。必填：`date`（日期）、`rating`（1—5 星）、`content`（正文）；支持常见中文别名。建议保留 `external_id`、`app_id`、`country`、`version`、`author` 和 `title`。

导入前须确认来源归属；文件中游戏或地区不一致、日期错误、非法星级会阻止本次导入，并列出错误行。无时区日期按中国时间。缺外部 ID 时用文件内容摘要和行号防止同一文件重复导入，匿名同文的两行保留；跨不同文件的同一评论无法可靠去重，优先提供评论 ID。示例数据不会进入正式工作流。

Excel 中的外部文本强制按文字保存；HTML 内容转义。所有游戏的文件夹导出先全部生成，再发布新的版本目录，不删除已有表格或用户文件。

## 备份与恢复

数据库位于 `data/reviews.sqlite3`，包含原始评论、修订历史、复核、巡检配置、提醒、事项及审计记录。升级前自动备份；页面「备份完整数据库」可手动创建并检查备份。备份位于 `data/backups`。建议重要处理后备份，并定期复制到其他存储位置。

恢复前关闭启动器。进入仓库根目录，使用安装依赖的同一个虚拟环境：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B restore_backup.py "C:\完整路径\reviews_备份时间.sqlite3"
```

恢复程序先验证备份，再保存当前库副本，然后恢复。不要用文件管理器覆盖仍在运行的 SQLite 数据库。恢复历史备份也会恢复该时间点的巡检配置和事项，重开后核对。

## 开发与验证

交付版本使用 Python 3.12.10，`requirements.lock.txt` 记录已验证的依赖版本。开发环境使用标准 Python 建立 venv，再安装锁定依赖；无需把数据、报告、运行环境提交到 Git。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -X utf8 -B run_checks.py
.\.venv\Scripts\python.exe -X utf8 -B launch.py
```

公开评论列表通常不提供评论对应的游戏版本。来源明确给出版本时标注「来源提供」并优先保留；来源缺失时，可按同一 App ID、同地区的商店版本发布时间区间显示「按日期推定」。推定结果不改写原评论 `topic`、正文或哈希，也不证明玩家实际安装了该版本。早于可用版本历史、晚于历史观测时间、发布日只有日期精度、时间冲突或缺失的评论保持未能确定。真实采集成功后自动尝试同步版本历史，缓存有效期 6 小时；历史同步失败不影响已保存评论。版本口碑图及问题类别/关键词筛选可使用该归属，界面保留来源与推定的区别。

首页只展示采集数量与评论日期；页码、覆盖判断与失败详情在「采集日志」查看，规则版本等在「采集与设置 → 运行诊断详情」查看。

`data/sample_reviews.csv` 的 61 条多平台记录均为合成示例，链接使用 `example.com`，仅供旧报告模块演示；不代表已经接入这些平台，也不会自动进入正式工作流。`tests/fixtures/appstore_reviews.json` 使用 `TestUser` 与虚构评论 ID。完整回归使用临时数据库、模拟采集响应与模拟 Agent，不需要真实评论库。一个依赖本机公开页面探测快照的可选测试会在源码版中跳过，其余版本历史解析有合成测试覆盖。

主要结构：`collectors/app_store.py` 采集；`collectors/app_store_public.py` 公开列表适配；`modules/review_store.py` 评论与修订；`modules/monitoring.py` 定时任务；`modules/operations.py` 统计和事项；`modules/alerts.py` 本地提醒；`modules/deliverables.py` 报告；`workbench_ui.py` 页面。`modules/dashboard.py` 图表统计；`dashboard_ui.py` 看板；`assets/dashboard.css` 深色主题。旧报告模块保留兼容。

自动回归覆盖图表分母、时区分桶、空样本、多主题计数、关键词去重、同游戏地区隔离及简化导出；另覆盖：否定句、星级冲突、未知语言、空数据、时间边界、更新评论、复核失效、游戏隔离、分页回退与防串库、失败重试、任务去重、处理留痕、导出失败保护、Excel/HTML 文本安全、备份恢复及数据库升级。真实联网验证了中、美两个地区各两页评论。尚不代表所有游戏/地区长期可用，也未完成大规模压力测试或长期人工准确率评估。
